# The honest number

Everything in this project is measured against this table. It was produced
before any new modelling approach was written, so the bar was not set with
knowledge of what would clear it.

Generated by:

```bash
python -m f1predict.evaluate.run_backtest --models baselines,original --view post_quali
python -m f1predict.evaluate.original_leak
```

## Protocol

**Walk-forward, rolling origin.** For each of the 103 races in 2022–2026, every
model is fitted on races dated strictly before it, then asked to predict that
one race. Training data grows race by race; no model ever sees a row dated on or
after the race it is predicting.

**Primary metric: top-1 winner accuracy** — did the highest-ranked driver win.
It is what the original approach targeted and it is the number a reader
understands without a footnote.

**Confidence intervals are bootstrapped over races**, resampling races rather
than driver-rows. The twenty rows of a single grand prix are not independent of
one another; treating them as such would shrink every interval by roughly a
factor of four and make everything look far more certain than it is.

**Why 103 races and not one season.** The strongest naive rule on this data
("the pole sitter wins") scores 0.455 in 2022 and 0.727 in 2026. At ~22 races a
season, the standard error on an accuracy is around 10 percentage points. A
single held-out season cannot distinguish a good model from a lucky one, so the
test window spans five.

### The number

**The original approach scores 0.456 top-1 (MLP) against a 0.573 naive
baseline.** It does not beat "assume the pole sitter wins", and the paired test
cannot separate the two with confidence either way. Any new approach has to
clear 0.456 to improve on the original, and 0.573 to be worth publishing at all.

### On the SVM

The SVM's 0.078 is not a broken fit. Its Spearman ρ of 0.532 is close to the
MLP's 0.573, and its scores correlate +0.48 with grid position — it orders the
field reasonably. What collapses is specifically its *top pick*: for the 2024
season opener it ranked Russell (P3 on the grid) above Verstappen (pole).

The cause is that `gamma=0.1, C=10.0, kernel='sigmoid'` were grid-searched
against the original 88-column, mostly-sparse feature matrix. In the rebuilt
25-column dense feature space those values no longer suit the data, and the
Platt-scaled probabilities lose their ordering exactly at the top. This is a
fair illustration of a real point — hyperparameters are properties of a feature
space, not of a model — but it is not a fair test of the original SVM. Retuning
it inside the walk-forward folds is tracked as follow-up work.

## Where the original 0.818 came from

The original notebook reported 0.818 precision for the SVM. That figure is
reproducible, and it is not fraud or fantasy — it is a small-sample artifact.
Running the original code path on the original committed `Data/Final.csv`, with
the original hyperparameters and splits:

| Configuration | Top-1 | Test races |
|---|---|---|
| MLP, clean split (train ≤2021, test 2022), leak present | 0.318 | 22 |
| MLP, clean split, leak removed | 0.182 | 22 |
| SVM, clean split, leak present | 0.409 | 22 |
| SVM, clean split, leak removed | 0.409 | 22 |
| MLP, second split, scored on all 22 rounds | 0.727 | 22 |
| MLP, second split, scored on rounds 12+ | 0.455 | 11 |
| SVM, second split, scored on all 22 rounds | 0.409 | 22 |
| **SVM, second split, scored on rounds 12+** | **0.818** | **11** |
| naive: pole sitter wins (2022) | 0.364 | 22 |

The last configuration reproduces the reported number exactly. **It was measured
on eleven races.**

At n=11, 9 correct out of 11 carries a 95% confidence interval of
**[0.48, 0.98]** — a width of 0.495, half the available range. The same model
scored over the full 22-race season gives 0.409. The headline was not wrong
arithmetic; it was a point estimate from a sample far too small to support it,
reported without an interval. The original write-up did flag that "the testing
set is comparatively small and can lead to different results" — that caution was
correct and is quantified here.

Note also what this corrects: rounds 12–22 genuinely were held out of that
training set, so this is **not** train/test contamination. It is sample size.

### The `status_*` leak, separately

`Data/Final.csv` carries `status_Finished`, `status_Illness`, `status_Incident`
and `status_Mechanical Issue` — the finishing status of the race being
predicted. The original feature matrix was built by dropping three columns by
name (`driver`, `podium`, `points`), so all four went into the model. Of 3707
rows, 681 have `status_Finished == 0`, and none of them is a race winner: the
model was told which ~18% of the grid to rule out before predicting.

Measured on the original data and split, that leak was worth **+0.136 top-1 to
the MLP** (0.318 → 0.182 when removed) and **+0.000 to the SVM**. So it is a
genuine defect, and it inflated one of the two models materially — but it is not
where the 0.818 came from. Two independent problems, one of which is easy to
mistake for the other.

`f1predict/data/contracts.py` makes this class of bug structurally hard to
repeat: every column is registered with the point in time at which it becomes
knowable, and unregistered columns are rejected rather than admitted. While
building this project that guard caught nine further post-race columns the new
feature pipeline had itself produced.

## What this means

1. The original approach is beaten by a one-line rule. That is the honest
   starting point, and it is what makes the rest of the project worth doing.
2. Two separate evaluation defects — a post-race feature and an 11-race test
   set — each produced a number that looked far better than the method was.
3. Neither was detectable without baselines and confidence intervals. Adding
   those was the single highest-value change in this repository.
